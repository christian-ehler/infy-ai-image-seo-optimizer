# Security policy

## Supported versions

Security fixes are made for the latest version published on WordPress.org. A fix ships as a new
version; older versions are not patched. Please update before reporting.

## Reporting a vulnerability

Please report security problems privately. Do not open a public issue, pull request or
support-forum post.

1. Preferred: use **"Report a vulnerability"** on this repository's **Security** tab (GitHub
   private vulnerability reporting).
2. Alternatively, email **support@infypress.com** with "Security" in the subject line.

Please include:

- the plugin version and WordPress version,
- the affected file, route or screen,
- steps to reproduce or a proof of concept,
- the impact you expect (for example: data exposure, privilege escalation, stored XSS).

We acknowledge reports within 5 working days, keep you informed while we fix it, and credit you
in the changelog unless you prefer otherwise. Please give us reasonable time to release a fix
before you disclose details publicly.

## Scope

In scope: the code in this repository as shipped in the WordPress.org package.

Out of scope: the AI providers' own services, WordPress core, other plugins, and the
infypress.com website (report those to their owners).
